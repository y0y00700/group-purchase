# MVP 설계 재검토 목록

작성 기준: 2026-10-28

## 관리 원칙

초기 설계는 MVP를 완성하고 검증할 기준선이다. 구현 이후 트러블슈팅에서 관측한 문제를 근거로 대안과 트레이드오프를 비교하고 변경 여부를 결정한다. 새 MVP 설계를 합의할 때 현재 선택·목적·재검토 조건·대안·비용·검증 방법을 이 파일에 함께 기록한다.

- 이 목록의 대안은 도입 결정이나 성능 개선 결과가 아니다. 현재는 코드 구현·측정 결과가 없다.
- 문제를 관측하면 재현 조건·로그·메트릭·DB 근거와 해당 항목을 연결한다. 실제 병목과 의도적인 장애 주입을 구분한다.
- 변경 전후에 같은 조건으로 성능·정합성·복구성을 검증한다. 유지·변경·보류 판단과 효과·부작용·잔여 한계를 남긴다.
- 수량 상한·취소 선후·승인 기한·결과 불명 시 확보 유지·중복 방지 등 합의한 업무 규칙은 대안에서도 검증한다.
- 항목별 상태는 재검토 후보 → 문제 관측 → 대안 비교 → 유지/변경/보류 → 재검증으로 관리한다. 변경하지 않은 판단도 기록한다.

PostgreSQL은 단일 서버·서비스별 DB와 계정으로 시작하기로 합의했다. 정확한 버전·자원·경로와 Kafka 세부 설정은 실행 구성에서 고정한다. Redis는 여전히 후속 검토 후보다. 실행 환경의 상세 합의는 [실행 환경과 초기 설정](../design/%EC%8B%A4%ED%96%89%20%ED%99%98%EA%B2%BD%EA%B3%BC%20%EC%B4%88%EA%B8%B0%20%EC%84%A4%EC%A0%95.md), 관측·검증과 초기 목표의 합의는 [관측과 검증 설계](../design/%EA%B4%80%EC%B8%A1%EA%B3%BC%20%EA%B2%80%EC%A6%9D%20%EC%84%A4%EA%B3%84.md)를 따른다.
