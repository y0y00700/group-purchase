# 개별 참여 상태 설계

작성 기준: 2026-10-26 대화 내용

관련 문서: [MVP 요구사항](MVP%20%EC%9A%94%EA%B5%AC%EC%82%AC%ED%95%AD.md), [프로젝트 개요](../%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8%20%EA%B0%9C%EC%9A%94.md)

현재 합의한 업무 규칙을 반영한 상태 초안이다. 공동구매와 참여는 같은 서비스에 두고 결제는 독립 서비스로 분리하기로 합의했으며, 근거는 [도메인 책임과 서비스 경계](%EB%8F%84%EB%A9%94%EC%9D%B8%20%EC%B1%85%EC%9E%84%EA%B3%BC%20%EC%84%9C%EB%B9%84%EC%8A%A4%20%EA%B2%BD%EA%B3%84.md)에 정리했다. 참여 상태는 공동구매 서비스가 관리하고, 결제 서비스에서 확인한 승인·환불 결과를 반영한다. 초기 서비스 경계는 해당 문서를 기준으로 하며, 데이터 모델·API·이벤트 계약은 후속 단계에서 정한다.

## 1. 상태 초안

`참여 신청 / 결제 완료 / 참여 취소 / 구매 확정 / 환불 대기 / 환불 완료`

참여 한 건의 업무 상태를 나타내며 기존 구성을 유지한다. 결제 시도의 진행 중·결과 확인 중·반영 완료와 확인된 승인 결과는 별도로 관리한다. 환불 진행도 구분해 추적한다. 상세 기준은 핵심 결제 흐름 설계의 2절을 따르며, DB 모델·API 필드·이력 보관 계약은 후속 설계에서 정한다.

## 2. 주요 전환

| 이전 상태 | 다음 상태 | 전환 조건 |
|---|---|---|
| 참여 없음 | 참여 신청 | 공동구매가 모집 중이고 남은 모집 수량이 있으며 참여 조건을 충족 |
| 참여 신청 | 결제 완료 | 유효한 시도로 기한 내 접수되었고 실제 승인 완료 시각이 해당 기한 미만이며, 구매자 취소로 제외되지 않았고 해당 건 전체 수량을 반영해도 기준 수량을 초과하지 않음. 결과 수신·반영은 마감 후에도 가능 |
| 참여 신청 | 참여 취소 | 구매자가 결제 전에 취소하거나, 결제 기한 종료·공동구매 구매 확정·최종 마감 처리에서 시스템이 미결제를 확정한 참여를 취소 |
| 참여 신청 | 환불 대기 | 실제 승인 완료 시각이 해당 결제 기한과 같거나 이후인 성공 건을 확인. 성립 판단에서 제외하고 전액 환불 |
| 결제 완료 | 구매 확정 | 취소되지 않은 결제 완료 수량이 기준 수량을 채워 공동구매의 구매가 확정 |
| 결제 완료 | 환불 대기 | 공동구매 구매 확정 전에 구매자 취소가 받아들여지거나, 필요한 결과 확인 후 최종 마감 기준 미달로 공동구매가 무산 |
| 참여 취소 | 환불 대기 | 구매자 취소가 먼저 수락된 참여에서 진행 중이던 결제의 승인 성공을 뒤늦게 확인. 성립 대상에는 다시 포함하지 않음 |
| 환불 대기 | 환불 완료 | 실제 환불이 완료된 사실을 확인 |

- 결제 후 취소를 받아들이면 `환불 대기`로 전환한다. 해당 참여는 이미 취소된 것으로 취급하며, 환불 완료를 기다리지 않고 성립 판단 수량에서 제외한다.
- 공동구매 구매 확정 후에는 구매자 취소를 허용하지 않는다.
- 공동구매가 재모집으로 전환되어도 취소하지 않은 기존 참여자는 `결제 완료`를 유지한다.
- 환불 처리가 완료되기 전까지 `환불 완료`로 바꾸지 않는다. 환불 실패·복구의 상세 방식은 후속 설계에서 정한다.
- 승인 진행 중 구매자 취소를 수락하면 `참여 취소`로 전환하고 실제 결제의 중단·결과 확인을 별도로 추적한다. 결과가 불명확한 동안에도 참여 취소는 유지한다.
- 구매자 취소 수락 뒤 승인 성공을 확인하면 `환불 대기`로 전환하고 전액 환불한다. 실제 환불 완료를 확인하면 `환불 완료`로 전환한다.
- 구매자 취소가 먼저 수락된 참여는 실제 승인이 기한 내였더라도 성립 대상에 복귀시키지 않고 환불한다.
- 구매자 취소가 없는 결과 불명 참여는 마감 시에도 즉시 참여 취소로 바꾸지 않고 결과를 확인한다. 그동안 신규 결제·재시도는 허용하지 않는다.
- 기한 내 실제 승인이 확인되면 마감 후에도 결제 완료로 반영할 수 있다. 기한 외 승인 성공은 결제 완료를 거치지 않고 환불 대기로 전환한다.

## 3. 결제 실패와 재시도

- 결제 실패가 확인되면 참여 상태는 `참여 신청`을 유지한다.
- 결제 기한이 남아 있고 공동구매가 결제를 접수 중이면 재시도를 허용한다.
- 기한 종료나 공동구매 구매 확정으로 미결제 참여가 취소되면 재시도를 허용하지 않는다.
- 참여 상태에 별도의 `결제 실패`를 추가하지 않는다. 미승인 확정·업무 반영·확보 해제 뒤 조건이 유효한 재시도는 새 결제 시도 ID로 기록하고 이전 이력을 보존한다.

## 4. 취소 후 재참여

- 공동구매가 모집 중이고 남은 모집 수량이 있으면, 취소한 구매자의 재참여를 허용한다.
- 재참여는 새로운 참여 건으로 생성한다.
- 이전 참여의 취소·환불 기록은 보존한다. 새 참여 건의 결제와 이전 참여 건의 환불은 각각 추적한다.

## 5. 구매 수량

- 판매자가 등록하는 **기준 수량은 최소 10개인 정수**로 제한한다.
- 최소 10개 조건은 최초 기준 수량에 적용한다. 재모집에서는 기준 수량을 유지하면서 실제 부족분만 모집한다.
- 최초 모집 목표는 **기준 수량 × 120%를 계산한 뒤 소수점 이하를 올림**한다. 예를 들어 기준 수량 11개이면 최초 모집 목표는 14개다.
- 한 번의 참여에서 여러 개 구매를 허용한다.
- 목표금액은 **판매자 기준 수량 × 상품 단가**로 계산한다. 재모집 중에도 이 기준을 유지한다.
- 같은 공동구매에서 **구매자 한 명의 유효 참여금액 합계가 목표금액의 10% 이하**여야 한다. 정확히 10%인 경우는 허용하고 초과하면 허용하지 않는다.
- `참여 신청`·`결제 완료`·`구매 확정` 참여의 금액을 합산한다. `참여 취소`·`환불 대기`·`환불 완료` 참여는 이미 취소되었으므로 합계에서 제외한다.
- 참여 건이 여러 개이거나 취소 후 새 참여 건으로 신청하더라도, 같은 구매자의 유효 참여 건을 합산해 상한을 적용한다.
- 신규 신청 시 **기존 유효 참여금액 합계 + 신청 수량 × 상품 단가 ≤ 목표금액 × 10%**를 충족해야 한다.
- 수량은 정수이므로 상한을 초과하지 않는 정수 수량까지만 허용한다. 동일 단가 기준 최대 합계 수량은 `판매자 기준 수량 × 10%`의 소수점 이하를 버린 값이다.

예: 판매자 기준 수량 100개·상품 단가 1만 원이면 목표금액은 100만 원이다. 구매자 한 명은 합계 10개·10만 원까지 참여할 수 있다. 이미 유효한 참여가 6개라면 추가 신청은 최대 4개다.

## 6. 취소 단위

- 취소는 **참여 한 건의 전체 수량**에 대해서만 허용하며, 일부 수량만 취소하는 기능은 제공하지 않는다.
- 여러 참여 건이 있는 구매자는 선택한 참여 건 전체를 취소한다. 다른 참여 건은 유지한다.
- 결제 전 취소는 해당 참여 건의 전체 수량을 취소하고 `참여 취소`로 전환한다.
- 결제 후 공동구매 구매 확정 전 취소는 해당 참여 건의 전체 수량을 성립 판단에서 즉시 제외하고 `환불 대기`로 전환한다. 해당 건에서 결제한 금액 전액을 환불한다.
- 공동구매 구매 확정 후에는 구매자 취소를 허용하지 않는다.

## 7. 기준 수량을 초과하는 결제

- **취소되지 않은 기존 결제 완료 수량 + 이번 참여 건의 전체 수량 > 판매자 기준 수량**이면 해당 결제 요청 건 전체를 거절한다.
- 남은 수량만큼 일부 결제하는 방식으로 자동 처리하지 않는다. 거절된 건의 수량은 결제 완료 수량에 반영하지 않는다.
- 초과로 거절된 참여 건은 `참여 신청` 상태를 유지한다. 결제 기한과 접수 조건이 유효하면 기존 재시도 규칙을 적용하며, 재시도할 때도 수량 상한을 다시 확인한다.
- 취소되지 않은 결제 완료 수량은 기준 수량 이하여야 하며, 정확히 기준 수량을 채우면 즉시 공동구매의 구매를 확정한다.

예: 기준 수량 100개에서 이미 98개가 결제되었다면, 3개짜리 참여 건의 결제는 전체 거절한다. 결제 완료 수량은 98개를 유지한다. 2개짜리 참여 건의 결제가 성공하면 100개가 되어 구매를 확정한다.

## 8. 후속 설계에서 정할 사항

- 동시 결제의 구체적인 제어 방식, 마감 결과 확인 중 진행 정보의 데이터 모델, 실제 승인 완료 시각의 연동 근거, 장기 결과 불명·환불 실패의 복구 상세 방식.

[핵심 결제 흐름 설계](%ED%95%B5%EC%8B%AC%20%EA%B2%B0%EC%A0%9C%20%ED%9D%90%EB%A6%84%20%EC%84%A4%EA%B3%84.md)의 1.1절에 공동구매 서비스가 맡는 Saga Orchestration, 5절에 진행 중 구매자 취소와 늦은 승인 처리, 6절에 마감 경합 처리의 합의 내용을 정리했다. 실제 승인 완료 시각을 기준으로 판정하며, 마감에 접수를 닫고 필요한 결과 확인 뒤 성사·재모집·무산을 판단한다. 마감 결과 확인 중에는 기존 구매자 취소 정책을 유지한다. 사전 수량 확보는 채택했으며, 3절의 원자적인 확보와 결과별 전환·해제, 결과 불명 시 유지 기준을 적용한다. 수량 확보만으로 참여를 결제 완료로 바꾸지 않는다. 2절의 참여 상태 유지·시도별 진행 구분·마감 결과 확인 중의 별도 공동구매 상태·202 접수와 결과 조회 방식을 합의했다. 구체적인 DB 모델·API 및 멱등성 계약·동시성 제어·복구 구현은 아직 미정이다. 위 후속 설계 항목은 한 항목씩 검토한다.
