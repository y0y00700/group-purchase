# 상품 정보와 판매 조건 수정 정책

작성 기준: 2026-10-26 대화 내용

## 1. 합의한 수정 범위

MVP에서는 판매자가 입력하는 아래 상품 정보와 판매 조건을 임시 저장 상태에서만 수정하고, 최초 게시 후에는 고정한다.

| 항목 | 임시 저장 중 | 게시 후 |
|---|---|---|
| 상품명·설명 | 수정 허용 | 수정 불가 |
| 상품 단가 | 수정 허용 | 수정 불가 |
| 판매자 기준 수량 | 수정 허용 | 수정 불가 |
| 최종 마감 | 수정 허용 | 수정 불가 |

임시 저장 정보의 수정은 해당 공동구매를 등록한 판매자만 할 수 있다. 게시 시 필수 정보와 기존 업무 조건을 다시 확인하고 판매 조건을 확정한다. 필수 필드와 입력 검증의 상세 구현은 데이터·API 설계에서 정한다.

## 2. 게시 후 적용 범위

- 최초 게시부터 고정한다. 첫 참여가 생길 때까지 수정할 수 있는 예외는 두지 않는다.
- 게시 직후 참여자가 없거나, 이후 모든 참여가 취소되어 유효 참여가 없어져도 판매자 수정 권한을 다시 열지 않는다.
- 재모집으로 돌아와도 최초 게시한 상품 정보·단가·기준 수량·최종 마감을 유지한다.
- 게시 후 임시 저장 상태로 되돌려 편집하는 기능은 MVP 범위에 추가하지 않는다.
- 고정 대상은 표에 명시한 판매자 입력 정보다. 공동구매·참여 상태, 모집·결제 완료 수량, 재모집 부족분, 회차별 결제 개시 시각과 기한은 기존 업무 규칙에 따라 변경한다.

회차별 기한이 새로 계산되어도 판매자가 설정한 최종 마감을 변경하는 것으로 취급하지 않는다. 새 기한은 기존 합의대로 회차 개시 후 168시간과 고정된 최종 마감 중 빠른 시각이다.

## 3. 이유와 비용

단가는 참여금액과 결제금액의 기준이다. 환불은 해당 건에서 실제 결제한 금액 전액이라는 기존 정책을 유지한다. 기준 수량은 성립 기준·최초 모집 목표·구매자별 10% 상한과 연결되고, 최종 마감은 모집·결제·무산 판정의 기준이 된다. 게시 후 이 값들을 고정하면 기존 참여 조건과 새로운 요청의 기준이 달라지는 문제를 줄일 수 있다.

상품명과 설명도 구매자가 판단한 상품의 내용을 바꿀 수 있으므로 MVP에서는 함께 고정한다. 오탈자만 허용하는 예외나 변경 이력·변경 안내 기능은 이번 초기 범위에 추가하지 않는다.

대신 오탈자와 잘못 게시한 정보도 기존 공동구매에서 수정할 수 없다는 불편이 있다. 다른 상품 정보나 판매 조건으로 모집하려면 새 공동구매를 수동 등록한다. 이는 기존 공동구매를 자동 취소하거나 기존 참여·결제·환불 기록을 새 공동구매로 옮기는 처리를 의미하지 않는다. 판매자에 의한 게시 취소·전체 중단은 이번 수정 정책의 범위에 포함하지 않는다.

## 4. 수정과 게시가 동시에 요청되는 경우

공동구매 서비스가 판매자 소유 권한과 임시 저장 상태를 확인하고 수정·게시의 선후를 원자적으로 판단한다. 상태를 먼저 조회한 뒤 무조건 덮어쓰는 처리로 게시 후 수정이 들어가지 않도록 한다.

| 먼저 반영된 처리 | 나중 처리 |
|---|---|
| 임시 저장 정보 수정 | 수정된 내용을 기준으로 게시 조건을 검증하고 게시 |
| 게시 | 판매자 정보 수정 요청 거절, 게시 시 확정한 정보 유지 |

DB 잠금·조건부 갱신·버전 검사 중 어떤 방식을 사용할지는 아직 정하지 않는다. 게시와 수정 요청에 대한 API·오류 응답도 후속 설계에서 정한다.

## 5. 검증 시나리오 후보

- 임시 저장 중 소유 판매자의 수정을 허용하고, 게시 시 기존 업무 조건을 검증하는지 확인한다.
- 다른 판매자의 수정과 게시를 허용하지 않는지 확인한다.
- 게시 직후 참여가 없어도 표에 명시한 정보의 수정을 거절하는지 확인한다.
- 모든 참여가 취소되거나 재모집으로 전환되어도 수정 권한이 다시 열리지 않는지 확인한다.
- 수정과 게시의 반영 순서를 바꾸어, 수정 우선이면 해당 내용으로 게시되고 게시 우선이면 이후 수정이 거절되는지 확인한다.
- 판매자 입력 정보가 고정되어도 정상적인 참여·취소·결제·재모집·마감 처리는 기존 규칙대로 진행되는지 확인한다.

위 정책을 합의해 MVP 요구사항과 도메인 책임 문서에 반영했다. 시나리오는 구현 후 검증할 후보이며 실제 테스트 결과는 아직 없다.
