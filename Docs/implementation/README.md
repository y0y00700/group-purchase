## 단계별 진행

1. `plan/`에 목표·현재 상태·관련 설계·범위·변경 예정 파일·선택 근거·대안·검증 방법·완료 기준을 작성한다.
2. 사용자가 읽고 수정 의견을 주면 같은 계획을 먼저 변경하고 반영 범위를 공유한다. 계획 수정 요청만으로 구현에 착수하지 않는다.
3. 사용자가 진행을 요청한 단계의 구현·필요한 검증을 완료한다. 합의한 범위 안의 세부 작업마다 승인을 반복하지 않는다.
4. 상위 `implementation/`에 같은 번호의 기록으로 실제 변경·실행 명령·검증 결과·남은 작업을 남기고 계획과 서로 연결한다. 결과 문서에는 아래 사용자 직접 테스트 방법을 필수로 포함한다.
5. 결과를 공유하고 다음 단계는 사용자의 진행 요청을 따른다.

계획 파일명은 `001-<english-task-name>.md`를 사용한다. 상태는 `검토 대기`, `진행 합의`, `구현 중`, `완료`로 관리하고 진행을 합의한 범위와 계획에서 달라진 내용을 기록한다. 실제로 수행하고 검증한 범위만 완료로 표시한다.

## 사용자 직접 테스트 방법

2026-10-30 사용자 요청으로 추가했다. 매 단계의 구현·테스트 결과를 공유할 때 사용자가 직접 재현할 수 있도록 결과 문서와 최종 안내에 테스트 경로를 제공한다.

- 준비 사항: 필요한 도구·버전, 작업 디렉터리, 사전 실행 서비스·포트·환경변수·테스트 데이터. 비밀값은 실제 값 대신 주입 방법을 설명한다.
- 실행 순서: 사용 환경에 맞는 복사 가능한 명령과 요청 예시를 제공한다. 여러 터미널이 필요하면 각각 구분한다.
- 기대 결과: 응답 상태·핵심 본문·로그 또는 저장 상태와 성공/실패 판단 기준을 적는다. 정상 흐름과 해당 단계의 주요 실패 상황을 포함한다.
- 종료·복구: 프로세스 종료, 임시 설정 원복, 테스트 데이터 정리와 재실행 방법을 적는다. 데이터 삭제가 필요한 명령은 영향 범위를 표시한다.
- 검증 상태: AI가 실제 실행해 확인한 항목과 사용자가 실행할 절차·환경 제약으로 미검증한 항목을 구분한다. 자동 테스트 결과만으로 수동 절차까지 검증했다고 표시하지 않는다.

후속 계획에도 사용자 직접 테스트 범위와 기대 결과를 완료 기준에 포함한다. 이미 승인한 구현 범위의 테스트 안내를 위해 별도 승인을 반복하지 않는다.
